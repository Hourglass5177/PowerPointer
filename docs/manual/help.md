# 常见问题与数据

先确认出错的环节：文件导入、页面读取、模型调用，还是内容保存。以下处理方式对应当前产品的实际行为。

## PPT 无法打开或版式异常 <!-- import -->

查看「导入记录」中的错误，再到「帮助 → 连接与环境检查」确认 PowerPoint 或 LibreOffice 是否可用。

如果转换软件不可用，可安装后重试，或先用其他设备将 PPT 导出为 PDF。遇到复杂版式、字体缺失或嵌入对象时，优先使用原 PowerPoint 导出的 PDF。动画、音视频不会在静态阅读页播放。

## 文字选不中或搜不到 <!-- scanned -->

先确认处于「选字」模式。扫描件或图片里的文字可能没有可提取的文字层，不能像普通文本那样选择和搜索。

改用「框选」，并选择支持图像的模型。仅文本模式不会自动识别扫描图片；本地全文搜索也不等于 OCR。

## 无法发送问题或模型报错 <!-- connection -->

检查当前连接是否启用、登录或密钥是否有效，以及模型是否仍可用。API 服务还需核对服务地址、协议和模型 ID。

如果提示不支持图像，可以换用图像模型；只有文字内容时才考虑仅文本模式。图表和扫描页不应通过关闭图像来代替正确配置。

额度、限流和服务错误按实际提示处理。获取到模型列表只能说明目录可读取，不代表模型推理一定成功；API 连接可以用「测试默认模型」进一步检查。

## 生成中断或结果待确认 <!-- interrupted -->

先查看错误和已保存的结果。章节整理可以「继续整理」或「重试未完成内容」；研究任务按当前状态继续处理。

对话断线不会自动重复发送。结果待确认时先核对记录，不要连续重试。新建会话会开始新的讨论，无法替代对旧任务状态的确认。

## 笔记或成果没有保存 <!-- saving -->

笔记自动保存；研究成果需要点击「保存修改」。两者都应以界面显示的保存结果为准。

保存失败后，保留当前浏览器中的草稿并处理错误。出现版本冲突时，可载入最新版本，或将草稿另存副本。清理浏览器数据可能丢失未同步的草稿。

## 来源为什么打不开 <!-- source -->

原课件已从应用中彻底删除时，旧问答或笔记可能仍保留文字，但来源无法打开。重新导入不会自动修复旧来源的对应关系。若只是「最近移除」，仍可从资料库重新打开课件。

目录中的原文件被移走，不会直接清除应用内已有版本。文件夹变更需要在「资料」中确认处理。

## 数据保存在哪里 <!-- data -->

课件副本、阅读位置、会话、笔记、成果和附件保存在本机应用数据目录；默认是项目下的 `data`。浏览器还会保存界面偏好和未完成的输入草稿。

普通阅读、搜索、查看历史和手动记笔记不需要模型推理。主动解释、提问、章节整理或研究时，会把本次需要的摘录、页面图像及相关背景交给所选模型服务。启用联网或外部工具后，还会发送对应的搜索词或调用参数。

## 备份与迁移 <!-- backup -->

1. 先确认笔记和成果已经保存，停止正在运行的任务，并关闭应用服务。
2. 复制完整应用数据目录，保留数据库、课件、阅读缓存和附件；只复制数据库并不完整。
3. 恢复时同样先关闭服务，再使用备份目录。若配置过自定义数据位置，应备份实际使用的目录。

Codex 的登录和模型线程状态存放在它自己的托管目录，单独备份应用数据不能保证旧模型线程继续可用。迁移到其他电脑或 Windows 用户后，API 凭据可能需要重新填写。

不要只依赖浏览器草稿或 Markdown 导出作为完整备份，也不要将含私有资料和凭据的数据目录公开分享。
